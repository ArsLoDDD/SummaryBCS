# Програми БЧС

Чотири прості локальні Windows-програми. Дані не передаються на сервер.

1. **Зведення БЧС** — об’єднує готові XLSX-файли підрозділів і порівнює БЧС за дві дати.
2. **Шаблон БЧС** — створює чистий XLSX під задану структуру.
3. **Редактор БЧС** — дає створити структуру, заповнити людей у програмі та експортувати XLSX.
4. **Редактор позицій по смугах** — веде позиції та екіпажі по кількох смугах, перевіряє статуси й формує один аркуш XLSX із загальним підсумком.

«Шаблон БЧС», «Редактор БЧС» і «Редактор позицій по смугах» автоматично зберігають чернетку після кожної зміни. Чернетка лежить у системній папці даних програми у зашифрованому форматі AES-256-GCM; ключ зберігається окремо з обмеженими правами доступу. Звичайним текстовим або Excel-редактором цей файл не читається.

## Перша версія

- імпортує два або більше `.xlsx`;
- приймає файли через системний діалог або перетягування у вікно;
- читає лише збережені значення клітинок, не виконує формули й не переходить за зовнішніми посиланнями;
- звіряє 16 колонок зі схемою RaportGen;
- визначає дату та назву підрозділу;
- відхиляє різні дати, дублікати файлів і підрозділів, макроси та пошкоджені архіви;
- дозволяє змінити порядок підрозділів перетягуванням;
- створює аркуш зі зведеною таблицею та заново обчисленими підсумками без формул у вихідному файлі;
- створює другий аркуш **«Аналітика»** з основними показниками й діаграмами поточного зведення;
- має окрему вкладку **«Порівняння»**: приймає БЧС за першу й другу дату та описує зміни в чисельності, відсутностях, екіпажах, місцях перебування, підрозділах і людях;
- порівнює як два БЧС одного підрозділу, так і два готові загальні БЧС або два набори файлів підрозділів;
- не показує в «БЧС по функціоналу» типи БпАК, для яких немає жодного екіпажу;
- не створює жодного службового аркуша: звичайний БЧС має лише аркуш **«БЧС»**, зведений — лише **«БЧС»** і **«Аналітика»**.

Значення «По штату» є номінальним вхідним реквізитом кожного БЧС і сумується між підрозділами. Воно не обмежує кількість рядків у структурі та не враховує прикомандированих, оперативно підпорядкованих чи тимчасово прибулих. Решта підсумкових показників обчислюється з нормалізованих рядків основної таблиці.

Аркуш «Аналітика» аналізує лише файли, завантажені в поточне зведення. Зміни між двома датами показуються в програмі у вкладці «Порівняння» та не додаються до окремого БЧС підрозділу.

## Локальний запуск кожного варіанта

Спочатку один раз встановіть залежності:

```text
npm install
```

Потім запускайте потрібний варіант окремою командою:

```text
npm run tauri:dev:summary
npm run tauri:dev:template
npm run tauri:dev:editor
npm run tauri:dev:strips
```

Короткі рівнозначні команди: `npm run app:summary`, `npm run app:template`, `npm run app:editor` і `npm run app:strips`.

Запускайте лише одну з чотирьох команд одночасно.

Повна перевірка:

```text
npm run test:full
```

## Збірка Windows EXE

Локально на Windows:

```text
npm run tauri:build:summary
npm run tauri:build:template
npm run tauri:build:editor
npm run tauri:build:strips
```

Вони створюють окремі виконувані файли `SummaryBCS.exe`, `BCSTemplateBuilder.exe`, `BCSEditor.exe` і `StripsEditor.exe`. Є також короткі команди `npm run build:exe:summary`, `npm run build:exe:template`, `npm run build:exe:editor` і `npm run build:exe:strips`.

У GitHub workflow **Windows EXE — збірка** автоматично запускається після кожного push у `main`; його також можна запустити вручну через `workflow_dispatch`. Він збирає «Зведення БЧС», «Редактор БЧС» і «Редактор позицій по смугах». Після завершення доступні три окремі ZIP-артефакти: `BCS-Windows-Summary`, `BCS-Windows-Editor` і `BCS-Windows-Strips`. Кожен містить NSIS `.exe`, публічний сертифікат `.cer`, відомості про підпис та інструкцію встановлення сертифіката. «Шаблон БЧС» у GitHub Actions поки не збирається. Pull request запускає лише перевірки без Windows-інсталяторів.

Кожен Windows EXE — як файл програми, так і NSIS-інсталятор — обов’язково підписується Authenticode із SHA-256 та міткою часу. Якщо PFX не заданий у GitHub Secrets, workflow автоматично створює резервний самопідписаний Code Signing-сертифікат; непідписаний артефакт не публікується. Для довіри до такого підпису вкладений `.cer` треба встановити на робочому ПК. Спільна політика успадковується всіма теперішніми та майбутніми Tauri-варіантами програми. Деталі описані в [docs/WINDOWS_CODE_SIGNING.md](docs/WINDOWS_CODE_SIGNING.md).

## Редактор позицій по смугах

Кожна смуга містить позиції з одним або кількома екіпажами. Поля позиції — підрозділ, тип БпЛА, позиція, її БГ, БРО, район і напрямок роботи — зберігаються один раз і в таблиці об’єднуються для всіх екіпажів цієї позиції. Район автоматично переводиться у верхній регістр. Засоби одного екіпажу записуються через кому.

Для позиції доступні статуси «БГ» і «Не БГ». Для екіпажу — «БГ», «Не БГ» і «Формується». Вибір «Не БГ» відкриває обов’язкове поле причини; без збереженої причини статус не застосовується. Для екіпажу зі статусом «Формується» поле БЧ автоматично стає «Формується» й блокується. Для інших екіпажів доступні «БЧ» та «Відпочинок після БЧ».

Основна статистика враховує тільки екіпажі, прив’язані до позицій, та позиції, де є хоча б один екіпаж. Позиції без екіпажів і екіпажі без позицій дозволені, але рахуються в окремому блоці. Позиція з кількома екіпажами завжди рахується як одна позиція. В експорті всі смуги йдуть послідовно на єдиному аркуші **«Позиції по смугах»**, а загальний підсумок розташований унизу.

## Простий порядок роботи

У «Шаблоні БЧС» та «Редакторі БЧС»:

1. Вкажіть назву, дату, тип структури та кількість за штатом. Дата за замовчуванням — завтра.
2. Для роти одразу створюються шість екіпажів, управління роти, управління взводу, відділення та блок «Інші». Управління роти є обов’язковим і не видаляється. Для взводу обов’язковим і невидалюваним є управління взводу; кнопки додавання управління роти та управління взводу в цьому режимі не показуються. Решту непотрібних блоків можна видалити.
3. Для кожного блоку вкажіть кількість людей. Для екіпажу також задайте окремі назву позиції та назву екіпажу, фактичну кількість людей, БРО, сектор роботи, назву БпАК, статус і тип БпАК.
4. У редакторі заповніть людей і оберіть місце зі списку.
5. Натисніть одну кнопку внизу та збережіть XLSX.

Масштаб усієї таблиці змінюється кнопками «−» і «+» у верхній панелі. Це впливає лише на відображення в програмі та не змінює експортований XLSX.

Усі списки в інтерфейсі кастомні. Управління роти, управління взводу та блок «Інші» можуть існувати лише по одному; їхні кнопки автоматично вимикаються, доки відповідний блок не видалено. Назви в колонці «Підрозділи по типу» починаються з великої літери, але не переводяться повністю у верхній регістр. Блок «Інші» має колір `D7E4BD`. Назва позиції, БРО, сектор роботи та назва екіпажу експортуються великими літерами. У П.І.Б. великими літерами записується лише прізвище.

Кожне створене місце для людини в будь-якому блоці потрібно заповнити. Для експорту обов’язково вказуються **Звання**, **П.І.Б.** і **Де знаходиться**. Поки хоча б в одному місці цих даних бракує, кнопка експорту неактивна та показує кількість незаповнених місць. Створення чистого шаблону XLSX залишається доступним без заповнення людей.

Правило таблиці: жоден текст не може виходити за рамку своєї комірки. Довгі назви та слова автоматично переносяться всередині комірки; це правило поширюється і на майбутні значення випадаючих списків.

Блоки завжди розташовуються в порядку основного БЧС: екіпажі, управління роти, управління взводу, відділення, інші постійні блоки, додані/придані та тимчасово прибулі. Цей порядок однаковий у редакторі, шаблоні й експортованому XLSX.

Для людей, які тимчасово прибули на посади ТВО, використовуйте окремий блок «Тимчасові з ТВО». Усі люди з цього блоку автоматично входять у «По списку», у загальний показник «Тимчасово прибулі» та в окремий показник «Тимчасово прибулі з ТВО». Старі БЧС, де ТВО зазначено в посаді людини зі звичайного блоку «Тимчасово прибулі», рахуються за тим самим правилом.

Для екіпажу «Кількість в/с» визначає, скільки людей додано в його список і скільки рядків для людей створено. «Фактично осіб в екіпажі» вводиться окремо й показує, скільки людей реально працює в екіпажі зараз. Ці числа можуть бути різними.

Підсумок у програмі та експортованому Excel використовує однакові правила. В Excel кожен екіпаж має окрему приховану ознаку першого рядка, тому кількість людей в екіпажі не може помилково збільшити показники «Екіпажів (загально)», типів БпАК або статусів екіпажів.

## Дані тестів

Тести створюють тимчасові XLSX з позначеннями `ОСОБА-001` та `ТЕСТОВИЙ ПІДРОЗДІЛ`; реальні ПІБ або робочі файли в репозиторії не зберігаються.
