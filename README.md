# Програми БЧС

Три прості локальні Windows-програми. Дані не передаються на сервер.

1. **Зведення БЧС** — об’єднує готові XLSX-файли підрозділів.
2. **Шаблон БЧС** — створює чистий XLSX під задану структуру.
3. **Редактор БЧС** — дає створити структуру, заповнити людей у програмі та експортувати XLSX.

«Шаблон БЧС» і «Редактор БЧС» автоматично зберігають чернетку після кожної зміни. Чернетка лежить у системній папці даних програми у зашифрованому форматі AES-256-GCM; ключ зберігається окремо з обмеженими правами доступу. Звичайним текстовим або Excel-редактором цей файл не читається.

## Перша версія

- імпортує два або більше `.xlsx`;
- приймає файли через системний діалог або перетягування у вікно;
- читає лише збережені значення клітинок, не виконує формули й не переходить за зовнішніми посиланнями;
- звіряє 16 колонок зі схемою RaportGen;
- визначає дату та назву підрозділу;
- відхиляє різні дати, дублікати файлів і підрозділів, макроси та пошкоджені архіви;
- дозволяє змінити порядок підрозділів перетягуванням;
- створює аркуш зі зведеною таблицею та заново обчисленими підсумками без формул у вихідному файлі;
- створює другий аркуш **«Аналітика»** з основними показниками й діаграмами поточного зведення;
- не показує в «БЧС по функціоналу» типи БпАК, для яких немає жодного екіпажу;
- не створює жодного службового аркуша: звичайний БЧС має лише аркуш **«БЧС»**, зведений — лише **«БЧС»** і **«Аналітика»**.

Значення «По штату» є вхідним реквізитом кожного БЧС і сумується між підрозділами. Решта підсумкових показників обчислюється з нормалізованих рядків основної таблиці.

Аркуш «Аналітика» аналізує лише файли, завантажені в поточне зведення. Тренди в часі — наприклад, зміну наявності чи станів за днями — потребують окремого багатоденного режиму з БЧС за кілька дат.

## Локальний запуск кожного варіанта

Спочатку один раз встановіть залежності:

```text
npm install
```

Потім запускайте потрібний варіант окремою командою:

```text
npm run tauri:dev:summary
npm run tauri:dev:template
npm run tauri:dev:editor
```

Короткі рівнозначні команди: `npm run app:summary`, `npm run app:template` і `npm run app:editor`.

Запускайте лише одну з трьох команд одночасно.

Повна перевірка:

```text
npm run test:full
```

## Збірка Windows EXE

Локально на Windows:

```text
npm run tauri:build:summary
npm run tauri:build:template
npm run tauri:build:editor
```

Вони створюють окремі виконувані файли `SummaryBCS.exe`, `BCSTemplateBuilder.exe` і `BCSEditor.exe`. Є також короткі команди `npm run build:exe:summary`, `npm run build:exe:template` і `npm run build:exe:editor`.

У GitHub workflow **Windows EXE — ручна збірка** (`workflow_dispatch`) збирає лише «Зведення БЧС» і «Редактор БЧС». Після запуску доступні два окремі ZIP-артефакти: `BCS-Windows-Summary` і `BCS-Windows-Editor`; кожен містить один NSIS `.exe`. «Шаблон БЧС» у GitHub Actions поки не збирається. Push і pull request збирають Summary та Editor, а спільні автотести також перевіряють генератор Excel.

## Простий порядок роботи

У «Шаблоні БЧС» та «Редакторі БЧС»:

1. Вкажіть назву, дату, тип структури та кількість за штатом. Дата за замовчуванням — завтра.
2. Для роти одразу створюються шість екіпажів, управління роти, управління взводу, відділення та блок «Інші». Управління роти є обов’язковим і не видаляється. Для взводу обов’язковим і невидалюваним є управління взводу; кнопки додавання управління роти та управління взводу в цьому режимі не показуються. Решту непотрібних блоків можна видалити.
3. Для кожного блоку вкажіть кількість людей. Для екіпажу також задайте окремі назву позиції та назву екіпажу, фактичну кількість людей, БРО, сектор роботи, назву БпАК, статус і тип БпАК.
4. У редакторі заповніть людей і оберіть місце зі списку.
5. Натисніть одну кнопку внизу та збережіть XLSX.

Усі списки в інтерфейсі кастомні. Управління роти, управління взводу та блок «Інші» можуть існувати лише по одному; їхні кнопки автоматично вимикаються, доки відповідний блок не видалено. Назва позиції, БРО, сектор роботи та назва екіпажу експортуються великими літерами. У П.І.Б. великими літерами записується лише прізвище.

Якщо в рядку людини введено хоча б одне значення, для експорту обов’язково потрібно вказати **Звання**, **П.І.Б.** і **Де знаходиться**. Поки цих даних бракує, кнопка експорту неактивна та показує причину. Повністю порожні рядки не вважаються людьми й не блокують створення порожнього БЧС.

Правило таблиці: жоден текст не може виходити за рамку своєї комірки. Довгі назви та слова автоматично переносяться всередині комірки; це правило поширюється і на майбутні значення випадаючих списків.

Блоки завжди розташовуються в порядку основного БЧС: екіпажі, управління роти, управління взводу, відділення, інші постійні блоки, додані/придані та тимчасово прибулі. Цей порядок однаковий у редакторі, шаблоні й експортованому XLSX.

Для екіпажу «Кількість в/с» визначає, скільки людей додано в його список і скільки рядків для людей створено. «Фактично осіб в екіпажі» вводиться окремо й показує, скільки людей реально працює в екіпажі зараз. Ці числа можуть бути різними.

## Дані тестів

Тести створюють тимчасові XLSX з позначеннями `ОСОБА-001` та `ТЕСТОВИЙ ПІДРОЗДІЛ`; реальні ПІБ або робочі файли в репозиторії не зберігаються.
